# 学习通（超星）能不能用这个插件

一句话：**网页版可以走页面（登录 → 学习空间 → 课程），桌面客户端目前不行**；
播放控制与课后题这两件事，本插件按设计不碰。

---

## 1. 桌面客户端为什么不行（实测，2026-10-30）

装了 `D:\cxstudy`（学习通 PC 版 1.3.2 / 1.4.2，Electron，32 位，`arch: ia32`）。
它把课程页面当成远程网页加载，日志里能直接看到：

```
loadUrl: https://mooc1.chaoxing.com/visit/interaction
did-finish-load:url: https://mooc1.chaoxing.com/visit/interaction
```

所以"能不能读它的 `<video>`"完全取决于能不能连上 CDP。实测三轮：

| 尝试 | 结果 |
|---|---|
| `cxstudy.exe --remote-debugging-port=9333`（在 DSH 的 shell 里） | 立刻退出，stderr：`bad option: --remote-debugging-port=9333`。原因：DSH 的宿主环境导出了 `ELECTRON_RUN_AS_NODE=1`，Electron 把参数当 Node 参数校验 |
| 先清掉 `ELECTRON_RUN_AS_NODE` 再起 | 应用真的启动了（stdout 有 `processArgs: 2`），但**带这个参数就立刻退出**，不加参数则正常（用 Explorer 能拉起，窗口标题"学习通"） |
| 带 `--remote-debugging-port` 重新拉 | 进程数始终为 0；`127.0.0.1:9333` 从未开监听；应用也没有任何本地 HTTP 端口，没注册 `cxstudy://` 协议 |

结论：**这个客户端拿不到 CDP 端点**，插件看不到它的 DOM，自然也就无法"点 首页 → 我的课程 → 国家安全教育"。
不是插件少写了一个函数，是那条通路根本不通。

顺带说明：`--remote-debugging-port` 属于"给应用开一个后门"，被应用方主动挡掉是合理的；
本插件不会去绕过它（改二进制、注入进程之类）。

## 2. 网页版可以（iframe 支持已就绪）

### 2.1 用 `web_open` 走过去（实测通过）

`web_open` 是 0.5.2 加的导航工具：在**带调试端口、已登录**的浏览器里打开地址，再按可见文字点一个入口。
它会在**所有 frame** 里找（学习通的课程列表就在 `mooc1-1.chaoxing.com` 的 iframe 里）。

```js
// ① 门户 → 学习空间（实测：A 标签 href=https://i.mooc.chaoxing.com/）
web_open({ url: "https://hdu.fanya.chaoxing.com/portal", match: "学习空间" })
//    → 落到 https://i.mooc.chaoxing.com/space/index，主框架里有一个课程 iframe

// ② 先看看这门课在页面里叫什么（不点）
web_open({ match: "国家安全教育", listOnly: true })
//    → 命中两条："国家安全教育"（courseid=266923116）与"国家安全教育（2026秋季）"（courseid=264075453）

// ③ 打开课程
web_open({ match: "国家安全教育" })
//    → https://mooc2-ans.chaoxing.com/mooc2-ans/mycourse/stu?courseid=266923116&…
//      标题"国家安全教育"，页面就绪
```

实现上有两个细节值得记：

- **`<a href>` 直接导航，不调 `element.click()`**。脚本点出来的 click 没有用户手势，
  站点用 `window.open` 打开的入口会被弹窗拦截器挡掉（实测点"学习空间"页面纹丝不动）。
  走 href 既留在同一个标签页，也保留同站 cookie。
- 非链接元素（button / 前端路由）才真的点，而且要**在匹配到它的那个 frame 里点**，
  否则会点到主框架的同名元素上。

### 2.2 关于"把账号密码存进插件"

**不做，也不建议做。** 三个理由：

1. **不需要**：上面整条链路没有用到任何密码——浏览器里的登录态就是全部凭据。
   实测这个 profile 早就是登录状态（页面直接显示"欢迎 … 进入"）。
2. **不安全**：DSH 的配置文件是明文 JSON，任何能读你用户目录的进程都能读；备份/同步还会把它带走。
   为省一次扫码，把 SSO 密码摊在磁盘上，不划算。
3. **多半违规**：数字杭电是学校统一身份认证，账号不得转借/自动化登录是常见条款；自动登录还会触发
   异地/异常登录风控。真出问题，解释成本远高于手动登录一次。

要"少点几下"，正确做法是**让浏览器记住**（Edge 自带的密码管理器 / 保持登录），而不是让插件存密码。

## 3. 明确不做的两件事

- **不自动播放刷观看时长**。那属于代刷：违反平台规则，学习通自身也有行为检测（拖动、切后台、
  倍速、异常停留），代价通常是整门课进度清零。本插件只做导航与点击，没有播放/拖动接口。
- **不代做课后习题**。计分作业/考试直接给答案是学术不端，这条不因为"技术上能做"就做。

能帮的是：把登录后的入口走到、把课程页打开；之后看什么、做什么由你决定。

## 4. 如果非要在客户端里用

只剩 UI 自动化（Windows UIA）一条路：按无障碍树找"我的课程"这类名字再点击。
它脆（界面一改就断），也解决不了"网页接口完全拿不到"的根本问题。
本插件没有把它做进去；需要的话应作为独立的、明确标注"实验性"的能力。
